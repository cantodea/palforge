# PalForge

面向 [SDLPAL](https://github.com/sdlpal/sdlpal) 的开放式游戏编辑器。目标不是只修改几个数值，而是把原版资源、剧情脚本、新美术、新玩法模块和快速测试放进同一个可扩展工作台。

> 当前版本是 **0.8 Animation Forge**。除了真实资源、场景、脚本编辑、单步推演和 SDLPAL-WASM 场景直达，它还提供独立的工程动画层：原版资源只读，自定义动画可编辑、保存、导入与导出。请保留合法取得的游戏数据，并始终使用副本。

## 现在能做什么

- 选择本地游戏目录，读取真实 MKF 偏移表并逐个浏览 chunk；
- 自动识别 DOS 版 `YJ_1` 与 Win95 版 `YJ_2` 压缩数据；
- 按 PAL sprite 帧偏移表解码 `MGO.MKF` 等资源中的 RLE 图像；
- 使用 `PAT.MKF` 的日间/夜间 VGA 调色板显示 sprite、RLE 与 320×200 FBP 图像；
- 在资源页连续混合日间/夜间调色板，并调节亮度、饱和度与对比度；
- 播放多帧 sprite，支持循环、1–24 FPS、进度拖动与逐帧检查；
- 从 `SSS.MKF #1` 建立真实场景目录，并用地图号关联 `MAP.MKF` 与 `GOP.MKF`；
- 解码 64×128×2 原版地图、底层/顶层图块、阻挡与高度位，并用 PAT 调色板显示；
- 从 `SSS.MKF #0` 取得场景事件范围，加载对应 MGO 精灵并显示真实坐标、方向、帧和脚本号；
- 从 `SSS.MKF #4` 读取真实事件脚本，按 8 字节记录显示 opcode、三个原始操作数、指令语义和显式跳转；
- 使用 `SSS.MKF #3` 的偏移表读取 `M.MSG`，自动尝试 GBK/Big5 并在文本指令上显示真实对白；
- 从场景进入/传送脚本以及事件触发/自动脚本直接跳到真实入口，并安全展开可达指令与越界诊断；
- 将任意真实入口克隆为工程脚本，编辑 opcode、三个操作数、对白和符号跳转，并增删、重排或逐步撤销指令；
- 使用稳定指令 ID 保持跳转关系；以追加式地址分配编译预览，生成原入口到新入口的重定向而不移动原脚本表；
- 在真实场景里调试进入、传送、事件触发或自动脚本，支持单步、连续运行、暂停、重置和地址断点；
- 让脚本对事件位置/状态/帧、队伍坐标和昼夜调色板的变化即时覆盖到场景画布，并显示调用栈与逐条执行日志；
- 对随机、战斗、确认框、存档条件及尚未模拟的指令暂停执行，由测试者明确选择分支或跳过，不伪造成功结果；
- 在隔离 iframe 中加载真正的 SDLPAL/SDL3 WebAssembly 引擎，从当前场景和安全图块跳过标题画面直接实机运行；
- 把已选择的本地游戏文件复制到临时 Emscripten `/data` 文件系统，关闭实机窗口即销毁实例，不写回源目录；
- 在 **Animation Forge** 中把一组 PNG、WebP 或 JPEG 按文件名顺序导入为工程动画，编辑帧顺序、时长、锚点和循环策略并实时播放；
- 用 `pal://` 表示只读原版引用，用 `project://animations/…` 表示可写工程动画；动画包只包含工程帧，不复制或覆盖原版 MKF；
- 导出可再次导入的 `.palforge-animation.json`，或导出透明精灵表 PNG 及包含裁切、时长和锚点的 `.sheet.json`；
- 将原始 chunk、解压结果或当前图像导出为文件；
- 在等距地图原型上选择、检查和绘制地形；
- 查看事件对象以及可读的脚本指令流；
- 将 PNG、WebP、音频和数据文件加入独立的 `forge://` 扩展命名空间；
- 管理编辑器、运行时桥接和小游戏三类模块；
- 从指定场景、坐标、等级、剧情标记或事件创建即时测试快照；
- 将编辑器工程保存到浏览器，或导出为 `.palforge.json`。

## 启动

需要 Node.js 20 或更高版本。

```bash
npm install
npm run dev
```

质量检查：

```bash
npm test
npm run build
```

## 查看真实资源

1. 启动后点击右上角 **打开游戏目录**，选择包含 `MGO.MKF`、`PAT.MKF` 等文件的目录。
2. 点击左侧 **资源**。页面左栏显示实际读到的 MKF 文件，中栏显示该文件的真实 chunk 编号、偏移和大小。
3. 选择 chunk 后，右侧会显示识别结果。sprite 可播放或逐帧查看；调色板工作台可选择 PAT、混合昼夜并调节颜色。
4. 通常保留 **自动识别**。若数据版本已知，也可强制选择 **DOS / YJ_1** 或 **Win95 / YJ_2**。

浏览器的目录授权不会跨刷新永久保存；刷新页面后需要重新选择目录。

## 查看真实场景与事件脚本

1. 点击 **打开游戏目录**，选择同时包含 `SSS.MKF`、`M.MSG`、`MAP.MKF`、`GOP.MKF`、`MGO.MKF` 与 `PAT.MKF` 的完整目录。
2. PalForge 会自动切到地图页；左侧场景树显示 `场景 #NNN / MAP NNN`，而不是演示场景名。
3. 点击任意场景读取对应 MAP/GOP 和事件 MGO。画布可以滚动、缩放，点击图块或事件后右侧显示原始字段。
4. 地图工具栏可以切换已挂载 PAT 的白天/夜晚调色板。当前操作只改变 Canvas 预览。
5. 选中事件后，右侧可以直接打开它的触发脚本或自动脚本；没有选中事件时可打开当前场景的进入/传送脚本。
6. 脚本页支持输入十进制或 `0x` 十六进制入口。黄色目标标签可以跟踪跳转/调用；右栏始终保留原始 opcode 与三个操作数。

## 编辑事件脚本

1. 在真实脚本页点击 **克隆到工程**。页面会切换成黄色的 `FORGE 工程覆盖` 状态，原始 `SSS.MKF #4` 不会变化。
2. 点击指令卡片，在右栏选择 opcode、修改 P0/P1/P2；已知跳转操作数可以改为指向工程中的任意稳定指令。
3. 使用卡片右侧按钮上移、下移或删除指令；底部按钮在当前指令后新增一条。地址会在编译预览中自动重算。
4. `0xFFFF` 指令会显示对白编辑框。新文本作为工程消息保存，编译预览为它分配追加的 M.MSG 编号。
5. **撤销一步**最多保留当前会话最近 50 次操作；**放弃覆盖**会恢复原版脚本视图。
6. 点击右上角 **保存工程**将脚本草稿保存到浏览器；**导出工程**会生成 version 3 `.palforge.json`，其中包含脚本草稿、编译预览、入口重定向和工程动画。

如果多个工程脚本互相调用，编译器会把调用目标改到对方的新入口。删除仍被跳转引用的指令、缺少停止指令、未知 opcode 或 16 位地址溢出都会在属性栏提示。
每个草稿还保存原脚本块的签名；换用不同版本的 `SSS.MKF` 时，编辑器会显示“基础脚本不匹配”，防止只凭相同入口编号误套补丁。
工程中有对白覆盖但未挂载 `M.MSG` 时，编译预览会报错并标记消息分配不安全；挂载完整目录后才会使用真实消息数量追加编号。

## 在场景中调试事件脚本

1. 打开完整 PAL 游戏目录，在地图页选择一个真实场景。点击图块会把它设为本次调试的队伍出生点；点击事件则会在右栏显示该事件。
2. 在右栏点击 **在场景中调试触发脚本** 或 **调试自动脚本**。未选事件时，也可以调试场景进入/传送脚本。
3. 底部 **场景脚本调试器** 会复制当前场景记录与全部事件对象。可在下拉框改选其他入口，然后点击 **建立场景沙盒**。
4. 使用 **单步**、**继续**、**暂停** 和 **重置** 控制执行；点击 **定位脚本** 可以在脚本页打开当前指令。
5. 在脚本页点击地址左侧圆点可增删断点。黄色高亮表示当前即将执行的指令。
6. 遇到随机数、战斗结果、确认框、等待按键、依赖存档的条件或未模拟指令时，调试器会停下来显示可选路径；选择后才继续。
7. 场景画布上的青色菱形代表调试队伍位置；事件的坐标、方向、帧、层级、显示状态和昼夜调色板会使用沙盒结果预览。右栏在调试时显示事件快照。
8. 脚本请求切换场景时会安全停止，并提供 **打开目标场景**；新场景不会被静默载入或继续执行旧上下文。

这是浏览器内的确定性场景沙盒，并不是完整 SDLPAL 进程。战斗、存档、声音播放及部分视觉效果只会记录或要求选择；原始 MKF、`M.MSG` 和存档不会被写入。工程覆盖参与调试前会检查 SSS 基础签名和编译错误。

## 创建、修改和导出自定义动画

1. 点击左侧活动栏的 **动画**。左栏“原版素材”只列出已挂载的 MGO/RNG/BALL/FIRE/FBP 文件，标记为 `READ ONLY`；点击它们会回到资源浏览器检查真实 chunk。
2. 点击 **新建模板**建立空动画，或点 **导入图片为动画**一次选择多张 PNG、WebP/JPEG。帧会按带数字的文件名自然排序，例如 `walk-2.png` 会排在 `walk-10.png` 前面。
3. 在时间轴选择帧，用右栏编辑单帧持续时间和脚底锚点；可以前移、后移、复制或删除帧。中央播放按钮会逐帧使用各自时长预览。
4. **导出动画包**生成标准 `.palforge-animation.json`。再次导入同一包时，相同 `project://animations/{id}` 会更新，其他工程动画不受影响。
5. **导出精灵表**会同时下载透明 PNG 和 `.sheet.json`；清单记录每帧矩形、持续时间与锚点，供以后 Runner 或模块适配器使用。
6. 右上角 **保存工程**将 version 3 工程快照写入浏览器；如果图片较多导致浏览器存储空间不足，请分别导出动画包并保存到磁盘。

Animation Forge 不会把自定义帧写进 `MGO.MKF`，也不会重新打包或覆盖任何原版文件。当前版本已经建立可共同寻址的 `pal://` 与 `project://` 两层，但工程动画尚未注入 SDLPAL 的角色/事件渲染表；下一阶段会增加显式资源绑定与临时运行映射。

## 使用 SDLPAL 实机运行当前场景

1. 打开完整 PAL 目录并选择一个真实场景；点击图块设置人物出生位置。
2. 底部脚本下拉框只控制 **建立脚本推演沙盒**，不会再控制实机的第一帧。
3. 点击 **从起点实机运行场景**。PalForge 会检查阻挡位和 SDLPAL 的接触触发范围；若落点位于门/传送触发区，会自动移到最近的安全半格。
4. PalForge 打开独立运行窗口，并把当前目录文件复制到 WebAssembly 内存文件系统。SDLPAL 会跳过商标、开场和主菜单，从安全坐标启动；场景进入与事件自动脚本仍由引擎自然执行。
5. 点击运行画面取得键盘焦点：方向键移动，Enter/Space 确认，Esc 打开菜单。
6. 点击 **重启**重新建立实例；关闭窗口会停止游戏并销毁临时运行文件。

实机运行器基于 `runtime/sdlpal/UPSTREAM_REVISION` 固定的上游提交。仓库 CI 在临时 checkout 中应用 PalForge 适配补丁并构建 `sdlpal.js`/`sdlpal.wasm`，不会向 SDLPAL 上游写入内容。安全落点的判定与 SDLPAL `kTriggerTouchNear` 距离公式保持一致；对应适配源码、补丁和许可证说明随仓库提供。

当前实机层运行挂载的原始 PAL 资源；Script Forge 的追加指令和对白已经能在脚本推演器里运行，但尚未注入 SDLPAL 的内存脚本表。下一步会把工程覆盖作为临时运行补丁送入 WASM，仍然不写回 MKF/M.MSG。

场景编号从 1 开始，地图 chunk 编号来自 SSS 场景表，两者不保证相同。二进制资源中没有可靠的中文场景名称，因此这一阶段使用编号显示。

## 设计边界

PalForge 将游戏原始数据视为只读输入，并把创作内容保存为独立工程：

```text
PAL 游戏目录 → 格式适配器 → PalForge 领域模型 → 编辑器
                                              ↘ 工程包
                                               ↘ Runner Bridge → SDLPAL 测试进程
```

这种结构让额外美术和新模块不必占用、覆盖原版资源编号，也让测试器以后能直接构造运行快照，不必每次从游戏开头打到目标流程。

当前只读资源、真实场景、工程层事件脚本、工程动画、浏览器脚本沙盒和 SDLPAL-WASM 实机运行链路已经打通；工程内容仍不会直接写回游戏副本。格式细节见 [资源格式说明](docs/RESOURCE_FORMATS.md)，模块拆分见 [架构说明](docs/ARCHITECTURE.md)。

## 路线图

- **0.1 · Forge Desk（完成）**：编辑器外壳、项目模型、MKF 索引、地图/脚本/资源/模块/测试工作流。
- **0.2 · Resource Lens（完成）**：YJ_1/YJ_2、sprite/RLE、PAT 调色板、FBP 预览与 chunk 导出。
- **0.3 · Scene Lens（完成）**：真实 PAL 地图、GOP 图块、事件对象、碰撞/高度和脚本引用的只读组合预览。
- **0.4 · Script Lens（完成）**：解析 `SSS.MKF #4`、覆盖 SDLPAL 已知 opcode，并提供场景/事件入口、可达流与跳转校验。
- **0.5 · Script Forge（完成）**：工程层事件脚本编辑、稳定跳转、追加式编译预览、对白覆盖和项目持久化。
- **0.6 · Scene Debugger（完成）**：在真实场景的只读内存快照中单步运行原版/工程脚本，提供断点、显式分支和状态叠加预览。
- **0.7 · SDLPAL Runner（完成）**：在浏览器隔离文件系统中运行真正的 SDLPAL-WASM，从指定场景和安全坐标启动。
- **0.8 · Animation Forge（当前）**：独立工程动画、帧时长/锚点编辑、实时播放、动画包和精灵表导入导出。
- **0.9 · Runtime Patch / Resource Binding**：把工程脚本、对白与 `project://` 动画映射注入临时 WASM 运行数据。
- **1.0 · Scene Forge / Native Runner**：实现地图/事件差异编辑，并提供稳定工程格式、模块 SDK 和 Windows 原生 SDL 测试进程。

PalForge 不包含《仙剑奇侠传》的游戏数据、美术、音乐或其他受版权保护的内容。仓库中的场景和台词只用于界面原型说明，正式发行前会替换为完全原创的测试素材。
