# PalForge

面向 [SDLPAL](https://github.com/sdlpal/sdlpal) 的开放式游戏编辑器。目标不是只修改几个数值，而是把原版资源、剧情脚本、新美术、新玩法模块和快速测试放进同一个可扩展工作台。

> 当前版本是 **0.4 Script Lens**。它会读取你选择的真实 PAL 目录，组合原版场景并解析事件脚本，但不会执行脚本或覆写原版文件。请保留合法取得的游戏数据，并始终使用副本。

## 现在能做什么

- 选择本地游戏目录，读取真实 MKF 偏移表并逐个浏览 chunk；
- 自动识别 DOS 版 `YJ_1` 与 Win95 版 `YJ_2` 压缩数据；
- 按 PAL sprite 帧偏移表解码 `MGO.MKF` 等资源中的 RLE 图像；
- 使用 `PAT.MKF` 的日间/夜间 VGA 调色板显示 sprite、RLE 与 320×200 FBP 图像；
- 在资源页连续混合日间/夜间调色板，并调节亮度、饱和度与对比度；
- 播放多帧 sprite，支持循环、1–24 FPS、进度拖动与逐帧检查；
- 从 `SSS.MKF #1` 建立真实场景目录，并用地图号关联 `MAP.MKF` 与 `GOP.MKF`；
- 解码 64×128×2 原版地图、底层/顶层图块、阻挡与高度位，并用 PAT 调色板显示；
- 从 `SSS.MKF #0` 取得场景事件范围，加载对应 MGO 精灵并显示真实坐标、方向、帧和脚本号；
- 从 `SSS.MKF #4` 读取真实事件脚本，按 8 字节记录显示 opcode、三个原始操作数、指令语义和显式跳转；
- 使用 `SSS.MKF #3` 的偏移表读取 `M.MSG`，自动尝试 GBK/Big5 并在文本指令上显示真实对白；
- 从场景进入/传送脚本以及事件触发/自动脚本直接跳到真实入口，并安全展开可达指令与越界诊断；
- 将原始 chunk、解压结果或当前图像导出为文件；
- 在等距地图原型上选择、检查和绘制地形；
- 查看事件对象以及可读的脚本指令流；
- 将 PNG、WebP、音频和数据文件加入独立的 `forge://` 扩展命名空间；
- 管理编辑器、运行时桥接和小游戏三类模块；
- 从指定场景、坐标、等级、剧情标记或事件创建即时测试快照；
- 将编辑器工程保存到浏览器，或导出为 `.palforge.json`。

## 启动

需要 Node.js 20 或更高版本。

```bash
npm install
npm run dev
```

质量检查：

```bash
npm test
npm run build
```

## 查看真实资源

1. 启动后点击右上角 **打开游戏目录**，选择包含 `MGO.MKF`、`PAT.MKF` 等文件的目录。
2. 点击左侧 **资源**。页面左栏显示实际读到的 MKF 文件，中栏显示该文件的真实 chunk 编号、偏移和大小。
3. 选择 chunk 后，右侧会显示识别结果。sprite 可播放或逐帧查看；调色板工作台可选择 PAT、混合昼夜并调节颜色。
4. 通常保留 **自动识别**。若数据版本已知，也可强制选择 **DOS / YJ_1** 或 **Win95 / YJ_2**。

浏览器的目录授权不会跨刷新永久保存；刷新页面后需要重新选择目录。

## 查看真实场景与事件脚本

1. 点击 **打开游戏目录**，选择同时包含 `SSS.MKF`、`M.MSG`、`MAP.MKF`、`GOP.MKF`、`MGO.MKF` 与 `PAT.MKF` 的完整目录。
2. PalForge 会自动切到地图页；左侧场景树显示 `场景 #NNN / MAP NNN`，而不是演示场景名。
3. 点击任意场景读取对应 MAP/GOP 和事件 MGO。画布可以滚动、缩放，点击图块或事件后右侧显示原始字段。
4. 地图工具栏可以切换已挂载 PAT 的白天/夜晚调色板。当前操作只改变 Canvas 预览。
5. 选中事件后，右侧可以直接打开它的触发脚本或自动脚本；没有选中事件时可打开当前场景的进入/传送脚本。
6. 脚本页支持输入十进制或 `0x` 十六进制入口。黄色目标标签可以跟踪跳转/调用；右栏始终保留原始 opcode 与三个操作数。

场景编号从 1 开始，地图 chunk 编号来自 SSS 场景表，两者不保证相同。二进制资源中没有可靠的中文场景名称，因此这一阶段使用编号显示。

## 设计边界

PalForge 将游戏原始数据视为只读输入，并把创作内容保存为独立工程：

```text
PAL 游戏目录 → 格式适配器 → PalForge 领域模型 → 编辑器
                                              ↘ 工程包
                                               ↘ Runner Bridge → SDLPAL 测试进程
```

这种结构让额外美术和新模块不必占用、覆盖原版资源编号，也让测试器以后能直接构造运行快照，不必每次从游戏开头打到目标流程。

当前只读资源、真实场景和事件脚本链路已经打通；真实地图/脚本双向编辑、资源写回和 SDLPAL 进程桥接仍在后续阶段。格式细节见 [资源格式说明](docs/RESOURCE_FORMATS.md)，模块拆分见 [架构说明](docs/ARCHITECTURE.md)。

## 路线图

- **0.1 · Forge Desk（完成）**：编辑器外壳、项目模型、MKF 索引、地图/脚本/资源/模块/测试工作流。
- **0.2 · Resource Lens（完成）**：YJ_1/YJ_2、sprite/RLE、PAT 调色板、FBP 预览与 chunk 导出。
- **0.3 · Scene Lens（完成）**：真实 PAL 地图、GOP 图块、事件对象、碰撞/高度和脚本引用的只读组合预览。
- **0.4 · Script Lens（当前）**：解析 `SSS.MKF #4`、覆盖 SDLPAL 已知 opcode，并提供场景/事件入口、可达流与跳转校验。
- **0.5 · Forge Builder**：以 PalForge 差异工程实现地图、事件和脚本的现代化编辑，并安全导出到副本。
- **0.6 · Runner Bridge**：以临时副本启动 SDLPAL，直接跳转到场景、战斗或事件。
- **1.0 · Forge Project**：稳定工程格式、模块 SDK、可复现构建和跨平台桌面包。

## 法律与资源

PalForge 不包含《仙剑奇侠传》的游戏数据、美术、音乐或其他受版权保护的内容。仓库中的场景和台词只用于界面原型说明，正式发行前会替换为完全原创的测试素材。
